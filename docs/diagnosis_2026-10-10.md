# 2026-10-10 项目现状与故障分析

> 本文为 2026-10-10 的记录快照；文中“下一次/后续”仅是当时判断。当前计划以 [PLAN.md](PLAN.md) 为准。

本次现场已因用户报告电量不足、断开连接而结束。原始录制、地图和诊断已保存至 Elements，所有本机实机观察/建图进程已结束。当前到达单狗服务器 SLAM 基线阶段；持续点云输入和地图几何尚未验收，双狗协同建图、导航与自主探索尚未实现。

## 当前已经获得的成果

- Go2 有线接入及真实点云、IMU、原厂里程计和状态接收通过。早先网口无载波已恢复，原因尚未确认。
- 保存了静止、用户遥控短直行、两次有效转向及其他静止诊断。原始记录与配置/版本建立对应；崩溃恢复包不计为正常运动样本。
- 单机服务器实时/回放链路接通：公共时间适配、一秒累积与逐点运动补偿、TF、SLAM、栅格地图和位姿图保存。
- 新转向包约 -38.66° 里程计转角，SLAM 约 -38.70°；地图重载逐格一致。里程计是 SLAM 输入，这属于内部一致性，不能替代独立精度测量。
- 当前 SLAM 包构建与 17 项检查通过。新增诊断工具在隔离环回域通过了电池原值写入、接收范围、断网分类和文件刷新检查；没有把合成数据计作实机证据。

地图仍有稀疏边界、射线和未知区域，未采集完整闭环，未完成独立尺度/形状测量。现有成果可用于展示单机接入和局部建图，但不能写成完整实验室地图、稳定导航或双机协同成果。

## 最新重启实验的正确解释

| 阶段 | 有效观察范围 | 点云接收频率 | 最大源间隔 | 本机新增接收错误 |
|---|---|---:|---:|---:|
| A：未重启，仅接收 | 五分钟 | 6.52 Hz | 6.23 s | 0 |
| B：未重启，同时建图 | 五分钟 | 6.44 Hz | 7.83 s | 0 |
| C：用户重启后，仅接收 | 约 92.27 秒在线前缀 | 14.51 Hz | 0.330 s | 0 |

C 阶段首个完整分钟为 14.72 Hz，最大间隔 0.079 秒；共 1,340 帧，五次间隔超过 0.25 秒。用户随后报告电量不足并断开，内核在 16:06:56 记录 Link Down，最后点云接收时间约 16:06:56.305。随后零消息与第二分钟整窗 7.61 Hz 包含离线时间，**不属于证明再次长时断流的数据**。

重启短时改善有证据，但原计划十分钟观察未完成。此前短试录也曾稳定，后续长时记录才变差；不能用这九十余秒宣布问题解决。重启前后姿态、实际电量和温度未完整登记，A/B/C 顺序实验不能区分所有变量。

## 各问题的原因判断

| 问题 | 已有证据 | 原因判断与把握 | 当前处理 |
|---|---|---|---|
| 长时点云 6–9 秒级缺口 | 不开本机 SLAM 仍发生；里程计约 150 Hz；消息内部逐点时间也跨 6–8 秒；末点至接收延迟波动约几毫秒；重启短时改善 | **优先检查机器人端雷达采集、内部传输、组帧或驱动状态**。范围定位有依据，具体部件未定位 | 保留原始时序和诊断，断流时重置累积，下一次充电后长时静止复现 |
| 电量不足 | 本次由用户报告；此前没有同步 BMS、电压和电流 | 是本次暂停原因，可能与断流有关，但**因果未证实**。仍低电量时重启短时恢复，不能用单一电量阈值解释全部现象 | 下次记录电量、供电、温度与同一时间轴上的缺口，不靠目测推断 |
| 温度、负载或供电状态变化 | 长时变差、重启短时改善符合多种状态变化；没有机器人侧负载/温度曲线 | 可检验的候选，证据弱于“上游采集/组帧异常”的范围判断；没有证据宣布过热、欠压或硬件损坏 | 同步采集可用温度/风扇/电池字段，申请合法的机器人驱动日志访问 |
| 电脑网卡/网络导致所有断流 | 早先确实无载波；恢复后 1 Gbps，A/B 没有新增网卡或 UDP 接收错误；长时间跨度已写入消息 | 早先链路故障真实存在，当前长时缺口由本机接收丢包解释的支持较弱；尚不能排除内部网络或所有短时故障 | 不贸然换驱动；只在满电稳定对照仍异常或再次无载波时做备用 USB 网卡/交换机对照 |
| ROS 2 停止运行弹窗 | 14:13:22 录制退出 134，异常明确为 SQLite database is locked；当时读取了正在写入的数据库 | **直接原因已确认：录制数据库读写锁冲突**，与电量或 SLAM 进程退出不能混为一谈 | 实时只订阅，关闭后读文件；resilient/WAL/五秒锁等待；后两组正常闭合；恢复 410,218 条已保存消息 |
| 断开后的 DDS 发送报错 | 内核 Link Down 后无法向指定有线接口发送发现数据；观察程序清理也持续重试 | 与主动断开一致，不能据此证明新的 ROS 崩溃；清理退不出是工具需处理的退出问题 | 报告保存后结束该进程；工具新增断网自动保存退出，防止持续重试 |
| 地图最初很差 | 单帧切片方向少；纯转向被平移门限阻止，旧图只有一个有效节点；短路线覆盖不足 | 已发现并修正处理问题；源缺口和场地杂物/遮挡仍限制结果 | 改为真实点累积、逐点补偿、运动门限；未知保留；需稳定采集及独立几何验收 |
| 点云相对时间超过三秒的报错 | 长缺口帧中相对时间可到约 8.66 秒；官方 SDK 定义其为点相对云头的时间 | 固定三秒上限与实测不符，属于已修正的适配问题；不能通过放宽上限补回缺失观测 | 依据实际时钟、窗口和姿态支持筛选近期点，保留源缺口 |
| 时钟差约 2173 秒、原始无 TF | 消息与记录时钟不同，机器人原始观测中未发现 TF | 是独立的时间/坐标适配问题，不能解释为雷达实际延迟 36 分钟 | 公共偏移每次重新估计，原始消息保留，本机补动态 TF，实时/回放已通过 |
| 无线接入尚未落实 | EDU 版本仅用户推测；App 配置尚未实际验证；当前走有线 DDS | 是未来网络部署任务，不是已有地图缺口的解决证据 | 后续单独确认硬件版本、无线配置和 DDS 发现；不在故障排查中同时切换接入方式 |

雷达状态的 `error_state` 在已记录样本中均为 0，只能说明没有通过该字段报告错误，不能证明数据连续性合格。SportModeState 的 `error_code=100` 与历史一致，语义尚未确认，不能将其当作本次新故障或正常证明。`cloud_packet_loss_rate` 的单位和机器人封装驱动含义未知，不直接标为百分比。

目前已知机器人雷达版本为 firmware 1.2.3、software 1.0.0.38、SDK 1.0.9。不同公开 SDK 的版本号不能直接证明机内组件不兼容；不据此自动升级固件。

## 已排查但不能过度下结论的事项

检查时本机内部盘仍约 26 GiB 可用，外盘约 763 GiB 可用，内存可用约 8 GiB，没有发现本次内存耗尽记录；录制崩溃给出了锁冲突异常。现有证据不支持磁盘耗尽或内存耗尽是该次崩溃原因，也不等于全面硬件压力测试通过。

当前响应地址的 SSH 和两个探测 Web 端口拒绝连接，雷达日志话题未收到内容；机器人驱动内部日志、CPU/温度与内部串口统计仍缺失。没有猜测密码、启动控制节点或修改机器人配置。

## 下一次实机排查顺序

1. **充足电量后的固定静止基线。** 记录开始电量、姿态、位置、朝向和启动时间；保持同一网络与场地，先十分钟仅接收，不运行服务器 SLAM。订阅并检查电池状态字段是否真实非零/有效。
2. **接上同样条件的建图对照。** 若前段稳定，再十分钟运行本机 SLAM；所有诊断订阅保持相同。比较源点云、供电、温度、错误字段和网络新增计数。
3. **按复现结果选择下一项。** 仅建图阶段异常时调查电脑资源/DDS 接收与额外订阅；两阶段均随时间异常时优先机器人侧驱动/雷达日志。高电量稳定而低电量反复异常时再验证供电关联；不为了复现故意耗到保护关机。
4. **稳定后才补移动和几何。** 固定墙面/门框、独立测量距离，用户遥控短直行/转向/小闭环；先检查地图尺度与墙面位置，再启用闭环，之后才推进导航和双狗。

暂定输入门槛为完整在线十分钟平均点云不少于 12 Hz、源间隔超过 0.25 秒的比例低于 1%、无超过一秒中断。这是项目内部验收门槛，不是厂商规格。满足后仍需几何精度验证。

## 离线期间可以继续的工作

用已保存数据固定单机回放与地图评估，补独立的几何/漂移指标接口；完成控制超时停车、人工接管和机器人命令隔离的模拟验证；用两个独立模拟实例开发坐标对齐、地图融合与目标分配。双狗实机证据仍需第二台到场，不能将一狗顺序数据当成双机同步成果。
