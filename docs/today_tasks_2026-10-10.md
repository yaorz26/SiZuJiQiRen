## 3. 需要采集的动作序列

| run label | 录制时长建议 | 人工动作 | 检查重点 |
|---|---|---|---|
| `smoke` | 30–60 秒 | 静止 | 录制可结束、数据非空、磁盘增长与时戳 |
| `static` | 2–3 分钟 | 机器人稳定站立 | 静态点云、姿态和里程计变化范围 |
| `straight` | 3–5 分钟 | 低速直行 2–3 m，停住；可重复 2–3 次 | 位置变化、前进方向、停止事件、数据连续性 |
| `turn` | 2–3 分钟 | 小角度转向并停住，例如左右各 90°；有条件再完整转一圈 | 朝向、点云坐标变化与雷达视野 |
| `loop_01` | 5–8 分钟 | 小范围矩形或闭环路径，回到有标记起点 | 地图回放所需观测；独立起终点位置与朝向 |
| `loop_02` | 5–8 分钟，可选优先项 | 重复相同路线和起点 | 相同场景的重复性 |

动作距离、角度与时长按场地缩小；先低速、短距离确认响应。录制前后各保留 10–20 秒静止。视频或事件表标记开始、前进、转向、停住、异常与人工接管。今天不必为了凑时长持续运动。

## 4. 现场录制入口

准备了 [单机采集脚本](../scripts/record_d1.sh)。脚本仅订阅并录制，不发布机器人运动命令。今日已有数据位于移动硬盘 `/media/yaorz/Elements/unitree_go2/experiments/2026-10-10_D1_go2_1`。后续新录制按当天日期、robot ID 和独立运行目录保存，可通过 `GO2_SESSION_ID`、`GO2_ROBOT_ID` 指定现场编号。开始前检查外盘挂载、可用空间和实际写入；检查失败时停止，不自动回退本机磁盘。

先使用当前已验证的 Go2 接入环境。现有 `/home/yaorz/unitree_ros2/setup.sh` 固定网卡为 `enp2s0`，只有该网卡确实连接机器狗时才使用；如当前终端已有可用连接，保留该配置。`setup_default.sh` 指向 Foxy，不作为今天的 Humble 入口。

在已验证的接入终端中加载本工作区，然后启动试录：

```bash
cd /home/yaorz/unitree_go2_ws
source install/setup.bash
bash scripts/record_d1.sh smoke
```

30–60 秒后按 Ctrl+C，等录制正常关闭。按终端输出的当次目录检查：

```bash
ros2 bag info /media/yaorz/Elements/unitree_go2/experiments/2026-10-10_D1_go2_1/实际运行目录/bag
```

确认有效后，依次录制；每条命令是独立一次运行，按 Ctrl+C 结束上一组后再开始下一组：

```bash
bash scripts/record_d1.sh static
bash scripts/record_d1.sh straight
bash scripts/record_d1.sh turn
bash scripts/record_d1.sh loop_01
```

脚本要求发现 `/utlidar/cloud_base` 与 `/utlidar/robot_odom` 的预期类型及运动状态话题。默认轻量录制保留 raw/body 点云、IMU、雷达状态、SportModeState、TF/静态 TF，不录运动命令出口；需要额外 deskewed 填充点云时明确使用 full 配置。录制使用 SQLite resilient、WAL 和锁等待。实时检查只订阅话题，必须结束录制后才读数据库。缺少必需话题时先排查连接，不能据脚本退出判断机器狗或项目本身不可用。

移动硬盘实际标签为 `Elements`，数据根目录是 `/media/yaorz/Elements/unitree_go2`；2026-10-10 检查剩余约 767 GiB，录制时以实际数值为准。后续原始录制、大点云、地图、视频和批量仿真数据优先写入该目录。脚本低于 5 GiB 时阻止启动，1 GiB 分片仅切分存储文件。两份备份应放在不同存储设备；同一移动硬盘的两个目录不算独立备份。
