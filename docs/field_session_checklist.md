## 2. 进场前至少 24 小时

- [ ] 候选版本已固定，完整启动、停止和记录在回放/模拟环境通过。
- [ ] 对应功能已有离线证据；涉及导航/探索的是动作改变观测的闭环模拟。
- [ ] 上次可用版本保留，回退不依赖现场下载。
- [ ] 本次主要目标、执行顺序、成功条件、失败后补采项已登记。
- [ ] 场地、机器人、电池/充电条件、独立接入设备和存储已确认。
- [ ] 默认大文件根目录 `/media/yaorz/Elements/unitree_go2` 已挂载且可写，原始数据、视频和地图直接输出到外盘。
- [ ] 原始数据目录、事件记录及独立备份位置准备完成；同一移动硬盘中的目录副本不算独立备份。
- [ ] 实机控制出口与回放/模拟控制输出区分清楚。

## 3. 到场后的检查与分工

- [ ] A/B 明确运动执行、观察和接管职责；双机时每狗有明确接管责任人。
- [ ] 核对 robot ID 与源数据、控制出口的对应关系。
- [ ] 先运行上次通过版本的短回归，检查传感器、时戳、状态、TF 和电量。
- [ ] 运动前检查停车、命令超时和人工接管；控制归属不明时停止运动测试。
- [ ] 开始录制后抽查真实数据，不能仅凭录制进程存在判断有效。

建议 8 小时预算：连接 0.5 h、短回归 0.5 h、主要验证 3.5 h、复位/电池处理 1.5 h、数据抽查 0.5 h、备份归还 0.5 h、问题机动 1 h。实际窗口更短时调整主要验证量，保留检查与备份时间。

## 4. 首个现场日 D1 的采集矩阵

| 优先级 | 数据片段 | 初始时长建议 | 必须记录 | 主要用途 |
|---|---|---|---|---|
| 必须 | 静止 | 2–3 min | 点云、原厂里程计、状态、源 frame 与时戳 | 检查坐标、静态噪声、时间基准 |
| 必须 | 人工低速直行与停止 | 3–5 min | 上述消息、人工动作事件与视频 | 平移方向、运动变化与数据连续性 |
| 必须 | 人工转向与停止 | 2–3 min | 上述消息、动作事件、角度标记 | 姿态、点云反变换与视野变化 |
| 必须 | 人工闭环路径 | 5–8 min | 感知、里程计、状态、闭环起终点依据 | SLAM 回放、地图质量与回到起点检查 |
| 有第二台时优先 | 第二狗静止及短运动 | 5–8 min | 独立 robot ID、接口、完整原始消息 | 第二管线预处理和数据归属 |
| 双机条件允许 | 同时接入、受控数据检查 | 约 5 min | 两狗数据、接入配置、身份和出口核验 | 原始 DDS 归属与隔离验证 |

时长是数据采集建议，未计连接、人工复位和电池处理。两台原始话题可能同名，先分别核对，不能直接把混流录制命名为双机数据。首次以人工控制采集；新自主动作需要通过对应阶段的控制验收。

至少带走两个存在明显运动变化的原始录制，并保留接口、外参/完整姿态、场地尺度和初始位姿标记资料。现有 CSV/PLY 不替代这些录制。

标记任务接受、目标变更、失败、取消、暂停、停车请求、实际停稳、掉线和恢复。软件发送停车请求与物理停住是两条不同证据。

## 6. 离场前必须完成

- [ ] 原始点云有有效载荷；直行和转向片段确实存在。
- [ ] 实际收到的 odometry / SportModeState 与对应 robot ID 一致。
- [ ] 时戳、frame、QoS、接口类型和缺失 TF 情况已记录。
- [ ] 数据文件可读取，抽查消息数量与时间跨度，检查事件能对应到原始录制。
- [ ] 代码/配置版本、初始位姿、布局、外参和必要标记照片保存完整。
- [ ] 保存成功与失败数据，不只留下演示视频。
- [ ] 复制到两份存储，至少抽查一份副本；保留原始录制。
- [ ] 停止自主控制与录制，记录机器人最终状态并完成归还。

现场诊断连续 30 分钟仍无明确方向时，回退已验证版本并补采症状。最后 30 分钟保留给抽查、备份和归还。

## 7. 离场后 24 小时结论

- 当次目标：通过 / 部分通过 / 未通过，并列明证据。
- 数据缺口：哪些能够离线修复，哪些需要下一次补采。
- 离线任务：问题片段、预期修改、验证方法和负责人。
- 下次前置条件：必须先关闭哪些问题。
- 下次唯一主要目标：优先安排无法离线确认的事项。
- 剩余实机次数与 D7 机动是否已被占用。

固定录制回放只能复现原轨迹，不能作为新导航/探索策略的闭环性能证据。回放时排除实机控制出口，模拟和真实实验分别标明。
