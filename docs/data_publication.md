## 为什么本次不整包上传 ZIP

原始录制约占总字节数的 98.55%，单文件最大约 885 MiB。
GitHub 对普通 Git 中超过 50 MiB 的文件给出提示，阻止超过 100 MiB 的文件；也建议通过文件分享服务分发大型数据库。
因此把这些数据换成 ZIP 并不能解决版本历史膨胀和下载负担，压缩率也尚未测量。
参见 [GitHub 官方大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。

若后续确需交付完整数据，可按一次实验一份归档，将 rosbag、元数据、配置与源码快照一并保存，
附上校验文件和对应代码提交，使用独立存储或按用途选择发布附件。
届时按接收方和平台限制确定格式与分包大小，无需现在制作一个包含所有重复及失败产物的总压缩包。

- [盘点摘要](data_inventory_2026-11-17.json)：范围、时间、文件数、按目录和扩展名统计的字节数及限制。
- [完整文件清单](data_inventory_2026-11-17.csv)：`path` 相对于外盘项目根目录，其余列为 `size_bytes`、`sha256`、`modified_at`。

- [10/10 数据索引](data_index_2026-10-10.yaml)、[10/25 数据索引](data_index_2026-10-25.yaml)：实验语义、输入、配置、报告和已知限制。
- [10/24 分析](offline_analysis_2026-10-24.md)、[10/25 结果](field_results_2026-10-25.md)：结论及证据边界。

SHA-256 标识的是盘点时的文件字节；它不证明实验有效、不替代数据库完整性检查，也不证明已有备份。
盘点时记录的工作区提交只是整理所依据的版本；每次实验的真实配置仍以该次元数据和快照为准。

例如 10/25 的 `angle_default` 回放目录实际使用了 `angle_variance_penalty=1.0`、
`minimum_angle_penalty=0.9`，与 Git 中默认的 `0.1/0.3` 不同；不能根据目录名或相同提交号认定参数相同。
