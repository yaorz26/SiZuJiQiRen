## 1. 目标与边界

项目目标（来源 [requirement.md](requirement.md)）：两台 Go2 在没有预先环境地图的室内平面区域中采集数据，由本机服务器完成定位、建图、地图融合、前沿探索与任务分配，机器人执行高层运动，最终形成共同地图并覆盖目标区域。

本轮采用集中式架构：每狗独立接入并在服务器上跑单机 SLAM，各狗地图经初始相对位姿对齐后融合，服务器统一分配目标，各狗沿用原厂高层运动接口。首轮假设两狗初始相对位置/朝向可测，这一条件必须在结果中披露。

本轮不做：任意初始位姿自动配准、三维全局闭环地图、第三台机器人、复杂学习型协同策略。

验收原则：原厂里程计是 SLAM 输入，只能做内部一致性检查；固定录制回放只能复现旧轨迹；模拟结果不能算实机；局部地图不能称为完整地图；未独立测量的几何精度保持“未验证”。

## 4. 技术主线与当前默认配置

```text
/utlidar/cloud_base (base_link)  +  /utlidar/robot_odom (odom→base_link)
        │ 每次运行估计同一时钟偏移
        ▼
go2_sensor_time_bridge.py  →  /go2/slam/cloud_base, /go2/slam/odom
        ▼
go2_accumulated_scan.py（1 s 真实观测累积、逐点姿态插值、按高度切片）
        ▼
/scan  →  slam_toolbox  →  /map, map→odom
        ▼
nav2_map_server / save_live_slam.py 保存、重载与逐格校验
```

当前默认值（详见 [bringup README](../src/go2_slam_bringup/README.md)）：

- 高度切片 `z ∈ [-0.2, 1.0] m`，量程 `0.2–5.0 m`，角度分辨率 `1°`；
- 累积窗口 `1 s`，点云缺口超过 `0.4 s` 清空窗口；未观测方向保留未知；
- 扫描发布门限：`0.05 m` 平移、`0.05 rad` 转角、最小间隔 `0.2 s`，静止每 `10 s` 刷新；
- `slam_toolbox`：`0.03 m` 分辨率，`minimum_travel_distance=0`、`minimum_time_interval=0.5 s`，闭环暂时关闭；
- 录制默认 light 配置，包含 raw/body 点云、里程计、IMU、雷达状态、运动状态与 TF；`GO2_RECORD_POWER_STATE=1` 增加 `/lf/lowstate`。

工具入口：

|---|---|
| 现场录制 | [scripts/record_d1.sh](../scripts/record_d1.sh) |
| 连续性观察/评估 | [check_go2_continuity.py](../scripts/check_go2_continuity.py)、[assess_continuity_report.py](../scripts/assess_continuity_report.py) |
| 运动摘要 | [summarize_motion_bag.py](../scripts/summarize_motion_bag.py) |

KISS-ICP 仍是候选里程计路线，不属于当前主线；构建说明见[归档文档](archive/2026-10-10/KISS_ICP_NEXT_STEPS.md)。

### S1：稳定输入 + 地图几何 + 闭环数据（10/25）

离线前置（今天/本周）：

- 用现有充电 A/B 数据跑完整回放与质量评估，复现静止位姿变化，判断主要来自原厂偏航还是扫描匹配；
- 固定候选版本，明天现场不再改算法；
- 准备卷尺、地面标记、相机、测量记录模板与地图端点选点流程；
- 确认 Elements 可写、机器人充满电、网线与网口状态。

现场顺序：

1. 接入、身份、电量、链路与话题核对；短时静止冒烟。
2. A：约 10 分钟仅采集，保持固定姿态/场景，记录 `/lf/lowstate` 电源原值。
3. B：相同条件约 10 分钟，启用服务器 SLAM；结束后保存实时地图快照与位姿图。
4. 用卷尺测两段可辨认的固定距离（墙边/门框），记录测量者、方法、不确定度、照片与端点标记。
5. 条件允许时，由用户遥控短直行 + 小转向 + 小闭环，回到地面标记起点；本机只录制。
6. 结束后检查原始包、报告、地图重载、元数据，复制备份。

通过条件：G1；地图保存/重载一致；两段独立距离已登记（几何结果可离线计算）；闭环起终点有独立标记；无崩溃、无多秒断流扩大。

失败处理：保留全部数据，不删失败报告；11/01 优先补测/诊断，导航阶段顺延。若 A/B 再次出现 >1 s 输入缺口，停止扩展运动，转输入诊断。

### S2：控制与到点导航（11/01）

离线前置：

- 参数化速度桥接：限速、命令超时自动停车、控制权/接管状态、命令归属；
- 停车与退出测试；与回放/模拟控制出口隔离；
- 安装并固定 Nav2 兼容版本（当前只有 `nav2_map_server`/`nav2_msgs` 等），完成启动配置；地图 + 定位方案二选一：保存地图 + AMCL，或在线 SLAM 定位；在回放/模拟中完成到点测试。

现场：

1. 先做 6 次短动作试验，测量命令延迟与实际停稳距离；超时、进程退出、人工接管均需产生停车请求。
2. 用 10/25 地图或现场在线地图，完成至少 3 个登记到点任务。
3. 任何控制归属不明或停车未验证时，不扩大自主运动范围。

通过条件：G3；至少 3 个到点任务有原始结果；无失控/无法接管。

### S3：导航批量任务、探索与双机资源门（11/08）

离线前置：

- 前沿提取与探索目标选择；失败/超时/取消处理；
- 双机命名、frame、唯一数据/命令出口、初始位姿对齐和地图融合的两实例模拟；
- 第二台机器人的接入与独立控制测试卡。

现场：

1. 累计 8–10 个登记导航任务，记录成功/失败、超时、人工干预和终点误差。
2. 条件允许时进行 5–10 分钟自主探索，验证新增地图与目标重选。
3. 第二台若到场：单独验证其运动/停车、数据归属和命令隔离；不与第一台结果混用。

资源门 R1（11/08 结束）：第二台是否确认可用、可同时到场、可独立接入。未满足则冻结“双机实机”路线，S4 起转单机 + 两实例模拟；双机结论只能标注为模拟/设计，不作为实机协同证据。

通过条件：G5；R1 有明确结论。

### S4：双机联调或单机探索加强（11/15）

- 有双机：A/B 各自单机 SLAM，测初始相对位姿，发布共同地图，完成一次 8–10 分钟双机运行；验证一狗暂停后任务释放/重分配（先静止后运动）。
- 无双机：更换障碍布局重复单机探索，保存视频与指标；用两个独立模拟实例完成融合/分配演示，明确标注模拟。

通过条件：G6（双机）或单机探索重复证据 + 模拟融合结果。

### S5：正式对照与演示录制（11/22）

- 双机可用：3 种策略各 2 次，固定版本、布局、起点、速度、分辨率与时间上限；记录失败/超时。策略 A：各自独立探索、不交换地图；策略 B：共享地图 + 固定分区；策略 C：共享地图 + 动态任务分配与失败重分配。
- 仅单机：固定场景重复探索/建图，形成可对比的前后结果与视频。
- 完成演示视频主体、图表和 PPT 骨架；此后不新增功能。

通过条件：G7；所有素材能对应固定版本与原始数据。

## 7. 分支与保底方案

保底目标（requirement 中的最低准备）：单机真实数据 → 时间/TF 正确 → 二维地图 → 保存/重载 → 质量报告 → 演示视频，加上双机集中式架构与两实例模拟；用于结项 PPT、报告和答辩。必须在材料中明确：双机实机协同未完成、地图为局部、几何精度范围有限。

触发条件与切换：

- **S1 后**：G1/G2 未通过 → 11/01 先补测/诊断；导航顺延一个窗口。
- **S2 后**：控制/导航未通过 → 11/08 继续修；探索不强行开展。
- **11/08 R1**：无第二台 → 冻结双机实机；S4–S6 以单机 + 模拟交付。
- **11/22**：若核心演示仍不稳定 → 缩小演示范围，保住“可构建、可回放、可复现”的成果，不用未通过数据填充 PPT。

优先级（时间不足时从高到低）：稳定输入与保存/重载 → 独立几何 → 到点导航 → 自主探索 → 双机实机。

- 链路断开、电量不足、机器人异常、用户要求停止：立即停止录制并保存。
- 运动阶段没有用户明确启动、或停车/接管未确认：不开始运动。
